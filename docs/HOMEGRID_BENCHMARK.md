# HOMEGRID_BENCHMARK.md — Fixed HomeGrid Evaluation Benchmark

> **Version:** 1.0  
> **Created:** 2026-10-28  
> **Purpose:** Evaluate the HomeGrid-Bot agent's existing capabilities and measure future improvements with a fixed, reproducible set of tasks.

---

## 1. Overview

This benchmark defines **10 fixed tasks** spanning all 5 task types supported by the HomeGrid environment and the agent's primitive skill set. Each task uses the exact natural-language format generated by `MultitaskWrapper.sample_task()` in the HomeGrid environment.

### Design Principles

- **Reproducible:** Tasks use the same strings the environment generates; run via `--task "..."` flag.
- **Complete coverage:** All 5 task types (find, get, open, cleanup, rearrange) are represented.
- **Graded difficulty:** Tasks progress from simple (single-skill) to complex (multi-skill composite).
- **Observable pass/fail:** Each task has an objective criterion checkable via `symbolic_state`.
- **No agent modifications required:** The benchmark tests the agent as-is.

### Environment Constants

| Category | Values |
|----------|--------|
| Pickable objects | `bottle`, `fruit`, `papers`, `plates` |
| Storage bins | `recycling bin`, `trash bin`, `compost bin` |
| Rooms | `kitchen` (K), `living room` (L), `dining room` (D) |
| Episode step limit | 100 steps |
| Agent retry limit | `MAX_RETRIES = 2` (up to 3 total attempts) |

### Primitive Skills Available

| Skill | Arguments | Description |
|-------|-----------|-------------|
| `find_object` | `(obj_name)` | Navigate to and face a named object |
| `pickup_object` | `(obj_name)` | Navigate to and pick up a named object |
| `open_bin` | `(bin_name)` | Navigate to and open a named bin |
| `put_in_bin` | `(obj_name, bin_name)` | Pick up → open bin → drop into bin |
| `move_to_room` | `(obj_name, room_name)` | Pick up → navigate to room → drop |

| **Task type** | find |

## 5. Important Notes and Limitations

### Environment Randomness

- **Object positions** are randomized on each `env.reset()`. The same task string may be easier or harder depending on the layout.
- **Bin open actions** (pedal/grasp/lift) are randomized per episode. The agent reads the correct action from `symbolic_state`, so this should not cause failures unless the bin enters "broken" state.
- **Task matching:** `main.py --task` resets up to 30 times to match the exact task string, then falls back to prefix matching. If the requested task is not sampled, a warning is logged and a different task is used.

### Statistical Validity

- Because of layout randomness, a single run per task is **not statistically significant**. For rigorous evaluation, run each task **N ≥ 5 times** and report the success rate.
- Future work: create an automated benchmark runner that executes each task N times and aggregates pass rates.

### What This Benchmark Does NOT Test

- **LLM hallucination recovery** — Tested indirectly via self-correction, but no task is designed to specifically trigger hallucination.
- **Multi-object tasks** — All tasks involve a single object. HomeGrid does not support multi-object goals in a single task.
- **Spill hazards** — HomeGrid can have spills that give `-1` reward; this benchmark does not specifically test spill avoidance.
- **Curriculum progression** — The benchmark runs tasks independently, not as a curriculum sequence.
- **Skill library growth** — Each run may add to `skills.json`; benchmark results may be influenced by existing learned skills.

### Unverified Behaviors

The following have **not been empirically verified** during benchmark design:

| Item | Status | Notes |
|------|--------|-------|
| `find the compost bin` via `find_object` | ⚠️ Unverified | `find_object` searches by name in `symbolic_state["objects"]`; bins are included in the object list, so this should work. Skill library has `find_compost_bin` with 3 successes. |
| `move_to_room` when object starts in target room | ⚠️ Unverified | `skill_move_to_room` checks if agent is already in room and calls `_drop_in_room`, but the object may not have been picked up yet if it's already in the target room. The `task_is_complete` check would need the object's `room` field to match. |
| Exact `--task` matching for rearrange tasks | ⚠️ Unverified | `main.py` resets up to 30+20 times; rearrange tasks may be rare. |

## 6. Extending the Benchmark

To add new tasks:

1. **Choose a valid task format** from the 5 supported types (see Section 1).
2. **Use object/bin/room names** that exist in HomeGrid (see Environment Constants).
3. **Assign the next sequential ID** (e.g., `BM-11`).
4. **Fill in all fields** following the template in Section 2.
5. **Update the coverage tables** in Section 3.
6. **Mark new tasks as unverified** until they are actually run.
